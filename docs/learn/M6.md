# M6 Crash test

## Što je napravljeno (datoteke)
- `scripts/chaos.py --kill-api-every 200 --restart-cmd "..."`: svakih 200 narudžbi ubije API **na tvrdo** (SIGKILL / TerminateProcess: nema gracefull gašenja, kao nestanak struje), dok je ~50 narudžbi u letu. Default naredba je `docker compose kill api && docker compose start api`. Ako naredba ne uspije, chaos.py pukne (`check=True`), da se ne bi mjerilo "kill" koji se nije dogodio (to se stvarno desilo u prvom pokušaju na Windowsima).
- `scripts/local_stack.py`: bez Dockera radi kao `restart: always`: ako API proces umre, digne ga ponovno.
- Ništa novo u API-ju: crash pokrivaju stvari iz M2-M5 (kratke transakcije, PENDING + reconciler, idempotency key = `order_id` prema provideru).

## Rezultat (lokalno, 3 runa, svaki 4 killa, FAIL_RATE=0.2 TIMEOUT_RATE=0.1)
Invarijante OK u sva 3 runa. Reconciler je pokupio 25-44 narudžbe ostale u PENDING (CANCELLED ili PAID). 56-88 klijenata je odustalo (`gave_up`), vidi granicu.

## Gdje je granica (što crash NE pokriva)
1. **Klijent ne dobije odgovor.** Ključ ostane PROCESSING, retry dobiva 409 dok klijent ne odustane. Novac i zaliha su točni (reconciler sredi narudžbu), ali klijent mora pitati podršku / pogledati narudžbe. Popravak: `locked_at` + preuzimanje starog ključa, ili da replay vrati stanje narudžbe.
2. **Narudžba visi do 60 s.** PENDING iz crasha se rješava tek kad je starija od `PENDING_STALE_S`. Kraće = rizik da reconciler otkaže narudžbu koju API baš plaća.
3. **Plaćanje nakon crasha se ne nastavlja.** Ako API umre prije poziva providera, narudžba se otkaže (CANCELLED) umjesto da se naplati. Outbox pattern (zapisati "treba naplatiti" u istoj transakciji, worker to odradi) bi je dovršio. To je bonus faza.
4. Fake-payments drži naplate u memoriji; test ubija samo API, ne providera ni bazu.

## Zašto ovako
- **SIGKILL umjesto `docker compose restart`**: restart šalje SIGTERM, a uvicorn tada lijepo završi zahtjeve u letu. To nije pravi crash.
- **Reconciler umjesto outboxa u v1**: manje dijelova; outbox je bonus.

## Pitanja za intervju
1. **API padne između COMMIT-a narudžbe i poziva plaćanja. Što se dogodi?**
   Narudžba je PENDING, zaliha skinuta, nitko nije naplaćen. Nakon 60 s reconciler je nađe, pita providera (`GET /charges/{order_id}`), dobije 404 → CANCELLED i vrati zalihu. Ako je naplata ipak stigla do providera → PAID.
2. **API padne nakon što je provider naplatio, a prije nego smo zapisali PAID?**
   Narudžba je PENDING, a provider ima naplatu pod ključem `order_id`. Reconciler je nađe i označi PAID. Nema druge naplate jer nitko ne naplaćuje s novim ključem.
3. **Kako bi to riješio bolje (outbox)?**
   U istoj transakciji kao narudžba upišeš red u tablicu `outbox` ("naplati order 42"). Zaseban worker čita outbox i zove providera s ključem `order_id`, pa red označi gotovim. Ako sve padne, worker nakon restarta nastavi gdje je stao. Narudžba se dovrši umjesto da se otkaže.
